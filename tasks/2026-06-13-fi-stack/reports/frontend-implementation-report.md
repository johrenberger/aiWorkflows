## Accessibility

- **UC2 (NewVisitForm)**:
  - `<label htmlFor>` for every input
  - `aria-invalid` on error
  - `aria-describedby` linking to error message
  - `role="alert"` on error messages
  - `role="status"` + `aria-live="polite"` (via the
    sr-only span) on success
  - Submit button shows busy state
  - `jest-axe` test passes
- **UC3 (PetTypeFilter)**:
  - WAI-ARIA 1.2 combobox pattern: `role="combobox"`,
    `aria-expanded`, `aria-controls`, `aria-autocomplete`,
    `aria-activedescendant`
  - Listbox with `role="listbox"` and options with
    `role="option"` and `aria-selected`
  - Keyboard navigation: ArrowDown, ArrowUp, Enter,
    Escape, Home, End
  - `aria-live="polite"` status region announces
    result count or selection
  - Click-outside to close
  - Loading and empty states are non-interactive
    (`aria-disabled="true"`)
  - `jest-axe` test passes

## Risks

- **`R1`**: The form uses a custom validation function;
  a real-world form would use a schema library (Zod,
  Yup). The skill's react profile doesn't mandate a
  library. Owner: future work.
- **`R2`**: The combobox implements the WAI-ARIA 1.2
  pattern by hand. A real-world component would use
  Downshift or react-aria for better coverage of
  edge cases. The skill explicitly forbids introducing
  new state-management libraries, but does not forbid
  a11y libraries. Owner: future work.
- **`R3`**: The proxy is the integration boundary; if
  the proxy is down, the UI is down. This is by design
  (the UI is for the proxy, not a fallback).
