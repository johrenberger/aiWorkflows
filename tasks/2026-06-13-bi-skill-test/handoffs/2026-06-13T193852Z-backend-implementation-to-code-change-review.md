## 10. Decisions made

- **`D1`**: Used `@Query` annotations on the Spring Data interface
  instead of relying on derived method names. Reason: derived names
  can't express `AND deletedAt IS NULL` (no equivalent keyword in
  Spring Data finder DSL).
- **`D2`**: Renamed `delete(Visit)` to `softDelete(Visit)` on the
  repository contract, instead of keeping the name and changing
  semantics. Reason: clearer at call sites; the controller already
  needed to update its single caller; the test
  `shouldDeleteVisit` was a one-line change.
- **`D3`**: Did NOT add a unique index on `deleted_at`. Reason: the
  java-spring profile forbids "cross-cutting concerns added without
  a clear current need", and there's no current query that
  benefits from such an index.
- **`D4`**: Did NOT add a "restore" method (re-set `deletedAt =
  null`). Reason: out of scope; the soft-delete pattern is
  one-way in this task.

  `TIMESTAMPTZ` would need an entity field type change. Likelihood
  low; impact low.
