## Plan

Add a soft-delete pattern to the `Visit` entity in
spring-petclinic-rest:
1. Add `deleted_at` (nullable LocalDateTime) column to `Visit`
2. `VisitRepository.delete(visit)` becomes a soft delete
   (`softDelete(visit)`) that sets `deleted_at` instead of
   removing the row
3. `findById`, `findByPetId`, `findByPetIdAndDateBetween`,
   `findAll` filter out soft-deleted visits
4. `Visit.isDeleted()` computed property
5. New tests: 2 covering soft-delete behavior

## Deviations from plan

- **`data.sql` files also needed updates, not just `schema.sql`.** The
  plan said "additive schema change", but the HSQLDB and MySQL
  `data.sql` use `INSERT INTO visits VALUES (...)` (positional),
  not `INSERT INTO visits (col1, col2, ...) VALUES (...)`. So adding
  the column broke the inserts. H2 and Postgres used named-column
  inserts, so they were unaffected. Total: 2 files updated, 4 rows
  per file. This is a side-effect of the additive migration, not a
  destructive change.
- **Added `findByPetIdAndDateBetween`** to the service interface
  even though the original plan didn't include it — but this
  method was already on the `VisitRepository` from use case #1
  (a different branch). Since the worktree is from `master` (the
  re-baseline), the method was not present, and the soft-delete
  task would have been incomplete without it. The implementation
  report reflects the worktree's actual state.
