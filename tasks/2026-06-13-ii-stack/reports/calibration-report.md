## Why `usable` (not `validated`)

The `usable` level requires "skill has been exercised and
produces valuable artifacts." That is met.

The `validated` level requires "skill has been proven to
catch issues a no-skill run would miss." The verdict is
**mixed** for this exercise:

| Metric | UC1 (no skill) | UC2-3 (with skill) | Δ |
|---|---|---|---|
| Time | 34 sec | ~3.5 min | +6x slower |
| Auditable artifacts | 0 | 2 (report + handoff) | +2 |
| Bugs caught by skill | n/a | **2** (see below) | +2 |
| Bugs introduced by skill | n/a | **0** | 0 |

**Net positive:** the skill caught 2 issues that a no-skill
run would have missed.

### What the skill caught

The skill's rest-api profile checklist explicitly required:

1. **Retry classification** — the skill mandated explicit
   `isRetryable` function. UC1 (no skill) would have
   either retried everything (wasteful, could 2x a write)
   or retried nothing (fragile). The skill produced a
   clear 5xx/429/network → retry, 4xx → no-retry
   classification. **This caught the 4xx-retry bug class.**
2. **Logging without secrets** — the skill mandated
   `logEvent` with a redaction list. UC1's `console.log`
   would have included `description` (free text may
   contain PII). **This caught a real PII-leak risk.**

### Honest verdict

The skill is **valuable for this domain**. The
integration-implementation profile is well-designed: it
mandates concrete failure modes, design checks, and
forbidden actions that map directly to real-world
integration bugs.

Compared to backend-implementation (which had a
**negative** verdict — the skill introduced a bug in UC3),
integration-implementation has a **positive** verdict
across all 3 use cases.

**However:** only 3 use cases. A confident `validated`
promotion would want 4+ use cases with at least one
demonstrating a clear, real-world bug catch. UC2 and UC3
have catches, but they're "structural" (would-have-been
bugs) rather than "observable" (actual bugs in a running
system).

## Recommendation

Promote `integration-implementation` to **`usable`** now.
Consider `validated` after 1-2 more use cases that
demonstrate a real catch in a non-trivial scenario
(e.g. catching a real upstream API change).
