## Operational lessons from this session

### PR creation pattern
- Token is parsed from `git remote get-url origin` via regex `x-access-token:([^@]+)@`
- `gh` CLI auth is broken; direct GitHub API works fine
- Helper scripts in `/tmp/` (e.g. `create_pr.py`, `inspect_pr15.py`) — pattern of one-shot Python scripts in `/tmp/` for one-off API calls
- `urllib.request` with `Authorization: token {token}` header is the only thing needed
- For 4xx errors, the response body has structured errors — print with `json.dumps(..., indent=2)`

### Skill maturity promotion pattern
- All promotions so far have been 1-line changes to `test-repo/skills/README.md`
- test-generation: `draft` → `usable` (PR #14-ish), then `usable` → `validated` (PR #15, `bdb3a89`)
- Pattern: 1 line in the skill inventory table, no SKILL.md changes needed for promotion
- Promotion PRs include evidence in the body (which agent reviewed, how many repos)

### Sub-agent invocation pattern (push-based)
- `sessions_spawn` returns a `childSessionKey`; do NOT poll
- Wait for `subagent_announce` completion event with `status: completed; ready for parent review`
- Sub-agent's report is delivered via inter-session message, not in the spawn response
- When sub-agent completes, the parent reviews the result before deciding what to do next
- Sub-agent's childSessionKey + runId + taskName are the only stable identifiers

### Cold-consumption test pattern (validated)
- Two inputs only: handoff-packet.md + spec.txt in `<app>-handoff-test/inputs/`
- Empty workdir at `<app>-handoff-test/workdir/`
- Sub-agent instructed NOT to look at canonical implementation
- Sub-agent writes a `HANDOFF_TEST_REPORT.md` with PASS/PARTIAL/FAIL
- Parent independently verifies by running the sub-agent's tests
- "Gaps" = decisions the sub-agent had to make that the packet didn't pin
- n=1 BDD-app test = 5 gaps (defined the gap fix)
- n=2 CSV-stats test = 0 gaps (validated the gap fix)
- n=2 with different shapes (full-stack vs CLI-only) is the threshold for `validated` maturity
