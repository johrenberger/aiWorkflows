## Operational lessons from this session

### PR creation pattern
- Token is parsed from `git remote get-url origin` via regex `x-access-token:([^@]+)@`
- `gh` CLI auth is broken; direct GitHub API works fine
- Helper scripts in `/tmp/` (e.g. `create_pr.py`, `inspect_pr15.py`) — pattern of one-shot Python scripts in `/tmp/` for one-off API calls
- `urllib.request` with `Authorization: token {token}` header is the only thing needed
- For 4xx errors, the response body has structured errors — print with `json.dumps(..., indent=2)`

### Skill maturity promotion pattern
- All promotions so far have been 1-line changes to `test-repo/skills/README.md`
- test-generation: `draft` → `usable` (PR #14-ish), then `usable` → `validated` (PR #15, `bdb3a89`)
- Pattern: 1 line in the skill inventory table, no SKILL.md changes needed for promotion
- Promotion PRs include evidence in the body (which agent reviewed, how many repos)

### Sub-agent invocation pattern (push-based)
- `sessions_spawn` returns a `childSessionKey`; do NOT poll
- Wait for `subagent_announce` completion event with `status: completed; ready for parent review`
- Sub-agent's report is delivered via inter-session message, not in the spawn response
- When sub-agent completes, the parent reviews the result before deciding what to do next
- Sub-agent's childSessionKey + runId + taskName are the only stable identifiers

### Cold-consumption test pattern (validated)
- Two inputs only: handoff-packet.md + spec.txt in `<app>-handoff-test/inputs/`
- Empty workdir at `<app>-handoff-test/workdir/`
- Sub-agent instructed NOT to look at canonical implementation
- Sub-agent writes a `HANDOFF_TEST_REPORT.md` with PASS/PARTIAL/FAIL
- Parent independently verifies by running the sub-agent's tests
- "Gaps" = decisions the sub-agent had to make that the packet didn't pin
- n=1 BDD-app test = 5 gaps (defined the gap fix)
- n=2 CSV-stats test = 0 gaps (validated the gap fix)
- n=2 with different shapes (full-stack vs CLI-only) is the threshold for `validated` maturity

### Lesson: PIT equivalent mutants
- `resetInternalMap()` clearing a map that won't be observed
  before being recreated → unkillable

  existing keys, so negation is equivalent

  mutations are equivalent

### Lesson: efficient PIT test design

  `contains*` methods (kills BooleanReturnVals mutants)

  key with a known value

  to deterministically trigger the switch

  the putAll'd keys is in the LRU" not "ALL of them"

## Memory file lesson #12: Decision file content is regex-matched, not parsed

The linter doesn't use a markdown parser. It uses `re.search(r"\\b(from_state)\\s*->\\s*(to_state)\\b")`. So:
- `from_state -> to_state` ✓
- `` `from_state` -> `to_state` `` ✗ (backticks around state names)
- `from_state → to_state` ✗ (unicode arrow)
- `from_state to to_state` ✗ (no arrow)

Always use the literal `->` with spaces. Backticks around the state names break the match.

## New rebase-conflict pattern (lessons #17, #18, #19)

All 3 Tier 2 PRs after #41 conflicted because they all touch `skills/README.md` lines 167-200. The fix is now established:

```bash
# 1. In the worktree:

# 2. Resolve by Python script (NOT interactive editor — OpenClaw can't handle that):

import re

t = open(p).read()
# Replace conflict markers
t = re.sub(r'<<<<<<< HEAD\n(.*?)=======\n(.*?)>>>>>>> .*?\n', r'\1\2', t, flags=re.DOTALL)

```

- Use `GIT_EDITOR=true` to avoid "dumb terminal" errors on `git rebase --continue` in OpenClaw sandbox
- Always use `--force-with-lease`, never `--force`

## New reproducer bug patterns (lessons #20, #21, #22)

### Lesson #20: backslash count in multi-line strings
`\\\\d+` in source (4 backslashes) → `\\d+` in memory (2 backslashes) → `\\d+` in file. The reproducer's `GOOD_REPORT = """..."""` triples the effective escape count. Use `re.sub` with a captured-group pattern to replace whole multi-line sections reliably:

```python
# Bad: string.replace("\\d+", "abc")
# Good: re.sub(r"## Old heading\n\n.*?(?=\n## )", "## New heading\n\n...", text, flags=re.DOTALL)
```

### Lesson #21: regex `re.findall` returns captured groups, not full match
`re.findall(r"(\bword\b)", text)` returns `['word']` not `[<Match>]`. Use `re.finditer` + `m.group(0)` for full match access. This was a bug in the security-review and runbook-authoring linters.

### Lesson #22: GitHub rebase with conflict markers in 3-way merge
When HEAD has skill A=validated, branch has skill A=draft, AND main has skill B=validated while branch has skill B=validated, the rebase produces a 3-way conflict. Resolution: take the union of validations — both A and B should be validated.

### Decisions made

- **`D1`**: Use `axios.request` (not `axios({...})`) so
  unit tests can mock with `jest.spyOn(axios, 'request')`.
- **`D2`**: Log only 7 safe fields (ts, level, event,
  correlationId, status, attempt, latencyMs). Never log
  `description` (free text), `petId`, or any user-supplied
  field.
- **`D3`**: Generate a correlation id if the client
  didn't provide one. Pass it downstream and return it
  in the response header.
- **`D4`**: Propagate `Idempotency-Key` header on POST.
- **`D5`**: Use PetClinic-REST as the local dev upstream
  (NOT a production endpoint, so allowed by rest-api
  profile's "do not call real production endpoints" rule).
- **`D6`**: Use a real local upstream for integration
  tests; mock for unit tests. This is the right split
  per the rest-api profile.

### New lessons (this segment)

- **#35**: For a Node/Express proxy, the existing upstream
  is "the local dev instance" — calling it from tests is
  allowed per the rest-api profile's intent (which forbids
  real production endpoints, not local dev instances).
- **#36**: `axios({...})` is the same as `axios.request(...)`,
  but the latter is more mockable via `jest.spyOn(axios, 'request')`.
- **#37**: When using a local upstream, tests are fragile
  to upstream state changes (e.g. pet 7's visit count
  changed during UC2 POSTs). Use pets that aren't touched
  by other tests.
- **#38**: LRU+TTL cache is a good "smallest safe" change
  for read-heavy endpoints; the cache invalidation logic
  is the key design check (what triggers invalidation).
- **#39**: Cross-stack skill exercise produces more
  confidence in the skill than same-stack exercise.
- **#40**: integration-implementation has a positive
  verdict (skill catches bugs), unlike backend-implementation
  which had a negative verdict (skill can introduce bugs).
